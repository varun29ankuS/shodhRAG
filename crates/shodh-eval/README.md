# shodh-eval

Measures shodh's retrieval and grounded answers on the real code paths:
folders are indexed with `indexing::index_folder` into a fresh, temporary
index; questions are searched with `RAGEngine::search_comprehensive` (what the
agent's `search_documents` tool calls); answers come from an omp agent session
with the library's document tools and the grounding verifier, as in the app.

## Datasets

JSON files of cases (see `src/dataset.rs`):

```json
{ "id": "msa-notice", "question": "How much notice ends the agreement for convenience?",
  "sources": [{ "file": "contracts/msa.pdf", "pages": [3], "passage": "ninety (90) days written notice" }],
  "facts": ["90 days"] }
{ "id": "none-ceo", "question": "Who is the CEO of Saffron Estates?", "answerable": false }
```

`file` is relative to the corpus folder. `"keep": false` drops a case.

## Committed corpus

`data/synthetic/` holds a synthetic corpus (fictional contracts and invoices as
paged PDFs with tables, research notes with Markdown tables, plain-text
policies; every name and number is invented) and 47 cases, 5 of them
unanswerable. It is generated by `src/synth.rs`; a unit test fails if the
committed files differ from the generator. Regenerate after changing it:

```
shodh-eval synth --out crates/shodh-eval/data/synthetic
```

No third-party texts are included.

## Commands

```
shodh-eval models    --models <dir>                       # pinned E5 + reranker (+ --answer-check: NLI model)
shodh-eval retrieval --corpus <dir> --models <dir> --dataset <file> [--runs 3] [--k 10]
shodh-eval compare   --baseline <file> --report <dir>/retrieval-report.json
shodh-eval generate  --corpus <your folder> --models <dir> --n 50
shodh-eval answers   --corpus <dir> --models <dir> --dataset <file> [--limit 10]
```

Outputs (`*-report.json`, `*-summary.md`, generated `questions.json`) go to
`.eval-local/runs/<folder>-<hash>/` unless `--out` is given; every output
folder gets a `.gitignore` of `*`. Questions, answers and reports about your
own folders stay there and are never committed.

**Retrieval metrics** (no LLM): `hit@1/5/10` and `mrr` over distinct
documents (a document counts once, at its first chunk), `page_hit@k` (a chunk
of an expected file on an expected page), `passage_hit@k` (a chunk containing
the expected passage), `ingest_ok` (files indexed / files seen). Search latency
p50/p95 is reported, never gated.

**Answer metrics** (opt-in; never in CI): `fact_recall`, `citation_correct`
(stated facts found in a passage the answer cites), `cited_expected_source`,
`claims_supported` and `flagged_per_answer` (the grounding verifier's
verdicts), `refusal_correct` on unanswerable cases, `false_refusal`,
`answered`. Refusals are detected by phrase; the report says which answers
were scored how.

## Language model (answers, generate)

Chosen with environment variables only; the eval never reads the app's
settings or key store:

```
SHODH_EVAL_PROVIDER=anthropic|openai|openrouter|google|xai|ollama|lm-studio
SHODH_EVAL_MODEL=<model id>
ANTHROPIC_API_KEY / OPENAI_API_KEY / OPENROUTER_API_KEY / GEMINI_API_KEY / XAI_API_KEY
```

Both commands send corpus passages to that model; use a local provider for
folders whose content must not leave the computer. `answers` downloads the
pinned agent runtime into `.eval-local/runtime` on first use (or set
`SHODH_OMP_PATH`). It differs from the app in what is not there: no app tools
(calendar, web, memory), no table refinement, no citation-graph ranking.

## Baseline and CI gate

`data/synthetic/baseline.json` is the committed corpus's retrieval baseline,
recorded from 3 fresh runs:

```
shodh-eval retrieval --corpus crates/shodh-eval/data/synthetic/corpus \
  --dataset crates/shodh-eval/data/synthetic/dataset.json --models <dir> --runs 3 \
  --write-baseline crates/shodh-eval/data/synthetic/baseline.json
```

`compare` fails when the dataset or corpus changed, a metric is missing, or a
metric is below `mean - max(3 * stddev, 1e-9)`. Retrieval is deterministic
(stddev 0), so any drop fails. A change that improves retrieval, or changes
the corpus or dataset, records a new baseline in the same PR. The `Retrieval
eval` CI job runs this on every PR.
